# 0013. E2E 失敗由主 agent 自己讀，不交給子代理

狀態：採用（2026-11-03）

## 背景

常見的建議是把資料收集交給子代理：子代理讀完大量 log 只回傳結論，主 agent 的上下文保持乾淨。
E2E 失敗時要看的有錯誤訊息、trace、頁面結構與網路請求，看起來正好適合。

但子代理從零開始，要自己重讀相關的程式碼與測試；而 E2E 失敗後主 agent 的下一步就是修它，
派出去之後多半只能等結論回來，沒有別的事可以平行做。

## 決定

E2E 失敗由主 agent 自己讀：先讀失敗測試的 `error-context.md`（錯誤訊息、出錯的那一行、當下的頁面結構，
通常幾十到一兩百行），看不出原因才打開 trace 的特定部分，不整份讀進來。省上下文靠精簡輸出
（本機的 Playwright 用 `dot`，只列失敗）與按需讀取，不靠換人讀。步驟寫在 `watch-pr` 這個 skill。

## 後果

- 修的人讀過失敗原因，不會因為只拿到摘要而漏掉細節；Claude 與 Codex 的做法一樣，不依賴哪一家的子代理功能。
- 一次大量失敗時主 agent 的上下文會變大。這種情況通常有共同的原因（環境沒起來、登入壞了），先看第一個失敗就找得到。
- 經常遇到分散在不相關功能、彼此無關的大量失敗時，重新檢討：那時每個功能派一個子代理平行分析才有平行的好處。
