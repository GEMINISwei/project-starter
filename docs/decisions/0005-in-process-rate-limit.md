# 0005. 限流計數放在行程記憶體

狀態：採用（2026-10-25）

## 背景

限流的計數常見放在 Redis。模板只有登入與改密碼需要限流，api 又是單一行程（見
[0004](0004-downtime-deploys.md)），為此多一個要維運與備份的服務不划算。

## 決定

`RateLimiter` 用行程內記憶體實作，對外只有 `check()`、`reset()`、`clear()` 三個介面。
需要多副本時，換成 PostgreSQL 當計數的儲存，理由與 [0006](0006-postgres-job-queue.md) 相同：不多開一個服務。

## 後果

- 不需要額外的服務。
- api 重啟時計數歸零。
- 加 workers 或副本會讓允許次數直接變成 N 倍，而且沒有任何症狀，所以**先換儲存，再加副本**。
- 換儲存只改 `RateLimiter` 的實作，呼叫端不用動。

現在的規則見 [限流](../features/rate-limit.md)。
