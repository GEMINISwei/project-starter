# 0004. api 維持單一行程：部署短暫停機、限流計數放記憶體

狀態：採用（2026-10-25）

## 背景

零停機部署要新舊版本並存，api 要能多副本；多副本又要求限流這類狀態放在共用儲存（主流是 Redis）。
模板只有登入與改密碼需要限流，為此多一個要維運與備份的服務不划算。

## 決定

- api 是單一行程，不加 workers 或副本。
- 部署時停機：先備份（nginx 停止），重建容器，healthcheck 通過後 nginx 才接回流量。
- `RateLimiter` 的計數放行程記憶體，對外只有 `check()`、`reset()`、`clear()`。

## 後果

- 部署與備份不用處理新舊版本並存；不用多一個服務。
- 每次部署都會中斷服務，要挑離峰時段；api 重啟時限流計數歸零。
- 加 workers 或副本會讓允許次數變成 N 倍且沒有症狀。需要擴充時**先把計數換成 PostgreSQL**
  （只改 `RateLimiter` 的實作，理由同 [0005](0005-postgres-job-queue.md)：不多開服務），**再**加副本，並重新檢討這份決定。

部署步驟見 [`operations.md`](../operations.md#生產部署)，限流規則見 [限流](../features/rate-limit.md)。
