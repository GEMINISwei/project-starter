# 0008. 不內建錯誤追蹤與告警

狀態：採用（2026-10-25）

## 背景

正式環境常見會接上錯誤追蹤（Sentry 之類）、結構化 log、指標與告警。
這些的做法依部署平台而定，而且錯誤內容可能帶著使用者資料，送不送到第三方是專案自己的決定。

## 決定

模板只提供寫到 stdout 的請求紀錄、貫穿三個服務的 request id，以及 Docker healthcheck。
錯誤追蹤、結構化 log、指標與告警都不內建，看 log 用 `make services logs`。

## 後果

- 模板不綁定任何第三方服務，也不會把使用者資料送出去。
- 出錯時沒有人會收到通知，要等使用者回報再上主機查。
- 瀏覽器端的錯誤在主機上完全看不到，這是最大的盲點。
- 重建容器時舊的 log 會消失。
- 上線給外部使用者，或需要主動發現錯誤時，先補錯誤追蹤（Sentry，或與它相容的自架 GlitchTip）。

現在有什麼、沒有什麼見 [`operations.md`](../operations.md#可觀測性只到-stdout)。
