# 0004. 部署會短暫停機，api 維持單一行程

狀態：採用（2026-10-25）

## 背景

零停機部署的前提是新舊版本能同時跑：api 要能有多個副本，流量才能在新版就緒後再切過去。
模板的 api 是單一 Python 行程，限流計數與部分狀態都在行程記憶體裡（見
[0005](0005-in-process-rate-limit.md)）。

## 決定

- 部署時停機：先備份（期間 nginx 停止），再重建容器，等 healthcheck 通過後 nginx 才接回流量。
- api 不加 workers 或副本。

## 後果

- 部署流程簡單，備份與 migration 不用處理新舊版本並存的情況。
- 每次部署都會中斷服務，資料越多中斷越久，要挑離峰時段。
- 需要零停機或水平擴充時，要先把行程內的狀態搬到共用儲存，再加副本，然後重新檢討這份決定。

部署步驟見 [`operations.md`](../operations.md#生產部署)。
