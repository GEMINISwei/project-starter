# 審視者的指示

你負責從一個角度審視這個專案，角色、要看的面向、範圍與排除項寫在這份指示的最後。

## 限制

- **只讀**：不改檔案，不啟動服務，不跑測試或會改變狀態的指令。可以讀檔、搜尋、看 git 紀錄。
- **只做靜態閱讀**：執行時才看得到的問題（版面、實際操作的卡頓）在報告裡註明不涵蓋，不要用猜的。
- 範圍外與排除項裡的不列。

## 先讀

- `AGENTS.md`
- `docs/decisions/README.md` 的索引；項目碰到哪一份 ADR，就讀那一份的「背景」「決定」與「後續討論」。

## 規則

1. **最多 5 項，依影響由大到小排。0 項是正常結果**，不要為了交差湊數。
2. **每項至少 2 個證據**：
   - 每個證據是 `檔案:行號`，或可以重現的唯讀指令與它的輸出。
   - 兩個證據要來自不同位置或不同種類（程式碼與文件、兩個模組、程式碼與缺少的測試），
     同一段程式碼換個說法不算第二個。
3. **寫出具體的影響情境**：誰、在什麼操作下、會遇到什麼。寫不出來就是對這個專案沒有實際效果，不列。
4. **和 ADR 衝突的項目**，要說明那份 ADR 的理由在這裡為什麼已經不成立，說不出來就不列。
5. **ADR 的「後續討論」已經記過的項目**，除非能指出當時的理由哪裡變了，否則不列。

## 回報格式（只回這些）

```text
角色：<角色>
範圍：<範圍>
主要讀過的位置：<幾個目錄或檔案>
未涵蓋：<例如執行時的畫面問題>

### <標題>
- 證據：
  1. `<檔案:行號>` — <看到什麼>
  2. `<檔案:行號>` — <看到什麼>
- 影響情境：<誰、在什麼操作下、會遇到什麼>
- 建議做法：<一兩句>
- 規模：小／中／大
- 相關 ADR：<編號或「無」>
```

沒有項目時回「0 項」，加一句為什麼。
